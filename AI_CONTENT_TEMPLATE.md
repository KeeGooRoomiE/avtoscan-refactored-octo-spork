# Методичка: как нейросеть должна оформлять тесты и вопросы

Этот файл — шпаргалка по формату данных для тестирования сотрудников «Автоскан». Отдайте его нейросети вместе с сырыми материалами (регламент, инструкция, транскрипт обучения и т.п.) и попросите вернуть готовые строки в этом формате — их можно будет напрямую положить в банк вопросов.

Формат хранения — [JSON Lines](https://jsonlines.org/): один JSON-объект на одну строку, без запятых между строками, без обрамляющих `[ ]`.

---

## 1. Две сущности и их связь

- **Тест** (в проекте также называется «раздел») — единица тестирования, привязанная к одной конкретной должности. Хранится в `data/tests.jsonl`.
- **Вопрос** — один вопрос внутри теста. Хранится в `data/questions.jsonl`, ссылается на тест через `test_id`.

```
Должность (mop / tp / service)
  └─ Тест (test_id, name)
       └─ Вопрос (test_id → тест, type, text, ...)
```

Один тест = одна должность. Если один и тот же материал нужен нескольким должностям — под каждую должность создаётся **отдельный тест** (можно с одинаковым `name`, это разрешено, но `test_id` у них будет разный).

---

## 2. Формат теста — `data/tests.jsonl`

```json
{"id": "test-a1b2c3", "position": "mop", "name": "Аттестация для менеджеров отдела продаж"}
```

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `id` | строка | да | Уникальный идентификатор. Формат: `test-` + 6 случайных hex-символов, например `test-8f2a01`. Если генерируете сами — просто убедитесь, что не совпадает с уже существующими id в файле. |
| `position` | строка | да | Ровно одно из: `mop` (отдел продаж), `tp` (техническая поддержка), `service` (отдел сервиса). Другие значения не валидны. |
| `name` | строка | да, непустая | Человекочитаемое название теста. Может совпадать с названием теста другой должности, но не должно дублироваться в паре с той же `position` — это одна и та же сущность. |

Больше полей нет (никаких `timer_seconds`, `description` и т.п. — их сейчас в модели нет, не придумывайте).

---

## 3. Формат вопроса — `data/questions.jsonl`

Общие поля для всех типов:

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `id` | строка | да | Уникальный идентификатор. Формат: `<слаг-названия-теста>-` + 6 случайных hex-символов. Слаг — название теста в нижнем регистре, пробелы и любые символы кроме `a-z0-9а-яё` заменены на `-`, лишние `-` по краям убраны. Пример для теста «Аттестация для менеджеров»: `attestaciya-dlya-menedzherov-4f9c21`. Главное — уникальность в пределах файла, точный слаг не критичен. |
| `test_id` | строка | да | `id` теста, к которому относится вопрос (см. раздел 2). Тест должен существовать. |
| `type` | строка | да | Одно из: `single`, `multiple`, `free` (см. ниже). |
| `text` | строка | да, непустой | Текст вопроса. |

**Полей `section`, `position_tags`, `points`, `manager_email` в модели вопроса больше нет — не добавляйте их.**

### 3.1. `type: "single"` — один правильный ответ

```json
{"id": "test-name-4f9c21", "test_id": "test-a1b2c3", "type": "single", "text": "Какой межповерочный интервал у тахографа?", "options": ["1 год", "3 года", "5 лет"], "correct": [1]}
```

- `options` — массив строк-вариантов, **минимум 2**.
- `correct` — массив с **ровно одним** индексом (0-based, индекс в массиве `options`).

### 3.2. `type: "multiple"` — несколько правильных ответов

```json
{"id": "test-name-91ab02", "test_id": "test-a1b2c3", "type": "multiple", "text": "Какие ТС подлежат оснащению тахографом?", "options": ["Грузовики > 3.5т", "Автобусы M2/M3", "Легковые M1", "Мотоциклы"], "correct": [0, 1]}
```

- `options` — массив строк-вариантов, **минимум 2**.
- `correct` — массив из **одного или нескольких** индексов (0-based), без дублей.

### 3.3. `type: "free"` — свободный текстовый ответ

```json
{"id": "test-name-c701de", "test_id": "test-a1b2c3", "type": "free", "text": "Какими приказами регламентируется деятельность в тахографии?", "answer_reference": "Приказ Минтранса №440 от 28.10.2020, приказ №438 от 26.10.2020, приказ №424 от 16.10.2020"}
```

- `options` и `correct` **не указываются вообще** (ни пустыми массивами, ни `null` — просто не включайте эти ключи).
- `answer_reference` — необязательное поле, справочный эталонный ответ **для проверяющего** (не для автопроверки — свободные ответы всегда проверяет руководитель вручную, глядя на `answer_reference` как на подсказку).
- Автопроверки правильности здесь нет и не будет — не пытайтесь придумать `correct` для free-вопроса.

## 4. Чек-лист валидности (что реально проверяется при публикации)

- `position` теста — только `mop` / `tp` / `service`.
- `name` теста — непустой.
- `test_id` вопроса — существующий тест.
- `text` вопроса — непустой.
- `single` / `multiple`: `options.length >= 2`, `correct` не пуст, индексы `correct` в диапазоне `options`; у `single` — ровно 1 индекс.
- `free`: `options`/`correct` отсутствуют.
- Все `id` уникальны в пределах своего файла.

Если хоть один пункт нарушен — публикация отклоняется целиком (частичного применения нет).

---

## 5. Примеры целиком

### 5.1. Новый тест с тремя вопросами (все три типа)

```jsonl
{"id": "test-7c3f10", "position": "service", "name": "Первичный инструктаж по технике безопасности"}
{"id": "pervichnyy-instruktazh-1a2b3c", "test_id": "test-7c3f10", "type": "single", "text": "Через какой срок проводится повторный инструктаж по ТБ?", "options": ["Раз в месяц", "Раз в полгода", "Раз в год"], "correct": [1]}
{"id": "pervichnyy-instruktazh-4d5e6f", "test_id": "test-7c3f10", "type": "multiple", "text": "Какие СИЗ обязательны при работе на выезде?", "options": ["Перчатки", "Каска", "Солнцезащитные очки", "Спецобувь"], "correct": [0, 1, 3]}
{"id": "pervichnyy-instruktazh-7a8b9c", "test_id": "test-7c3f10", "type": "free", "text": "Опишите порядок действий при обнаружении неисправности оборудования на объекте", "answer_reference": "Остановить работу, обесточить оборудование, сообщить руководителю, зафиксировать в журнале"}
```

### 5.2. Добавление вопросов в уже существующий тест

Если тест уже есть (`test_id` вам дан или найден в текущем `data/tests.jsonl`), новую строку `tests.jsonl` создавать не нужно — только вопросы:

```jsonl
{"id": "attestaciya-dlya-menedzherov-b2c3d4", "test_id": "test-mop-attestaciya1", "type": "single", "text": "Что делать при обнаружении нарушения пломбировки тахографа?", "options": ["Игнорировать", "Сообщить в сервисный центр и приостановить эксплуатацию", "Заклеить самостоятельно"], "correct": [1]}
```

## 6. Как применить готовый результат

Два варианта, в зависимости от того, кто и как будет заливать данные:

**А. Вручную через редактор (`editor.html`)** — самый безопасный способ: открыть страницу редактора, создать тест/вопросы руками, скопировав текст и варианты из ответа нейросети. Ничего технического не требует, но медленнее при большом объёме.

**Б. Напрямую в файлы** — если правите `data/tests.jsonl` / `data/questions.jsonl` в репозитории напрямую (не через редактор), просто дописать сгенерированные строки в конец соответствующего файла и закоммитить. Файл должен остаться валидным JSONL (каждая строка — отдельный `JSON.parse`-совместимый объект, кодировка UTF-8, без BOM).

**В. Через diff для `workflow_dispatch`** (если автоматизируете публикацию программно, в обход UI редактора) — тот же набор объектов оборачивается в:

```json
{
  "tests": [
    { "op": "add", "test": { "id": "test-7c3f10", "position": "service", "name": "Первичный инструктаж по технике безопасности" } }
  ],
  "questions": [
    { "op": "add", "question": { "id": "pervichnyy-instruktazh-1a2b3c", "test_id": "test-7c3f10", "type": "single", "text": "Через какой срок проводится повторный инструктаж по ТБ?", "options": ["Раз в месяц", "Раз в полгода", "Раз в год"], "correct": [1] } }
  ]
}
```

(`op` для правки существующей записи — `"edit"`, с дополнительным `"id"` на том же уровне, что и `"test"`/`"question"`; для удаления — `"delete"` с одним `"id"`, без тела объекта.)

и отправляется как `inputs.diff` (строкой, `JSON.stringify` от этого объекта) в workflow `edit-questions.yml`. См. `scripts/apply_question_diff.py` — именно он это обрабатывает и валидирует.

## 7. Заготовка промпта для нейросети

```
Вот методичка по формату данных (файл AI_CONTENT_TEMPLATE.md из репозитория) и сырые материалы по теме [тема].

Составь [N] вопросов для теста «[название]» (должность: [mop/tp/service]) строго в формате JSONL,
как описано в методичке. Используй разные типы (single/multiple/free) в разумной пропорции,
не изобретай поля, которых нет в методичке. Каждый id должен быть уникальным.
Выведи готовые строки, ничего кроме них.
```
